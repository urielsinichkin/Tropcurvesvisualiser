1. Getting started

This tool builds and studies combinatorial types of rational plane tropical curves. Each one is a tree with a direction on every edge, balanced at every vertex, possibly with marked points. You create types, derive new ones from them by contracting edges, resolving vertices and adding markings, and compute their refined multiplicities and evaluation matrices. Everything runs in your browser. All arithmetic is exact, and the library is saved automatically on your device.

A first session:

  1. The app opens with a sample curve (a 4-ended curve) selected. To start another, press New and pick a preset or draw a subdivision (Creating types).
  2. The middle of the screen shows the curve. Its dual subdivision sits below, folded.
  3. The Edit panel on the right has the type's name, its refined multiplicity, and Actions: edit an end's slope, add a marking, contract an edge, resolve a vertex, and build the evaluation matrix.
  4. Contracting or resolving creates a derived type. It appears under its parent in the Types panel on the left, and follows later edits of the parent (Derived types & propagation).
  5. Your work is kept in this browser. Use Export…, Import or ☁ Drive… to move it between devices or to share it.
Every panel and dialog has a ? button. It explains what that part does and links back here.

2. Concepts

  • Type (combinatorial type): a tree whose vertices are joined by bounded edges, with ends (unbounded rays) and markings attached to vertices. The library holds many types.
  • Direction and weight. Every bounded edge and end has an integer direction vector. Its weight is the gcd of the coordinates: (4, 0) has weight 4 and primitive direction (1, 0). Weights above 1 appear in labels, e.g. e1 (w4).
  • Balancing: at every vertex, the outgoing direction vectors sum to zero. Bounded edges' directions are solved from the ends by balancing.
  • Marking: a marked point, a contracted end with direction (0, 0). It sits at a vertex, or part-way along an edge. In that case the edge is split in two by a new vertex, and the marking hangs there.
  • Valence of a vertex: the number of edges, ends and markings meeting there. A curve is trivalent when every vertex has valence 3. A vertex with valence ≥ 4 can be resolved.
  • Crossing: a way of splitting a vertex whose new edge would have direction 0. It is realized as a parallelogram in the dual subdivision, not as an edge, so it cannot be applied.
  • Derived type: a type made from another (its parent) by contracting an edge or resolving a vertex. Types form a forest, shown as a tree in the Types panel.

3.2 Panels, phones and tablets

  • Resizing: on a wide screen, drag the thin bars between the columns to widen or narrow the Types and Edit panels. Double-click (or double-tap) a bar to restore its default width. With a bar focused, ←/→ resize it (with Shift in bigger steps). Widths are remembered per browser.

  • Narrow screens (phones, a portrait iPad, below about 900px): the columns stack (Types, then the curve, then Edit), and the top-bar buttons move behind the ☰ menu button.
  • Everything works with a mouse, a finger or an Apple Pencil (§16).

4. Creating types — New

The New type dialog creates an independent root type in three ways:

  • Presets: Tropical line (unit triangle), a single vertex with three ends; or 4-ended curve (unit square), two vertices joined by one bounded edge.
  • Draw a subdivision…: opens the visual editor (below). The curve is the dual of the subdivision you draw.
  • or paste as text: one cell per line, each a list of lattice points, e.g. [[0,0],[1,0],[0,1]]. A JSON list of cells is also accepted. Press Create from text. Parallelograms become crossings.

4.1 Drawing a subdivision

  • Click lattice points to trace a cell. Click the first point again, or press Finish cell, to close it. Cells are shaded as you go. Parallelograms are marked with × (in orange) and become crossings.
  • x … to …, y … to … with Resize grid changes the lattice window.
  • Undo point removes the last point of the current cell. Delete last cell removes the last finished cell. Clear starts over.
  • The status line counts cells, parallelograms and the points in the current cell.
  • Create curve builds the type. Show text shows the cells as text, with Copy, for reuse in the paste box.

5. The types panel

  • Selecting: click (tap) a type to show it in the curve view and the Edit panel. The selected type is highlighted.
  • Tree: derived types are indented under their parent, in derivation order.
  • Each row shows the name, then the counts (ends, bounded edges, markings), and for a derived type follows or detached (§10). If the type has a description, its first line appears in italics; hover over the row to see all of it.
  • Folding: ▾/▸ next to a type hides or shows its derived types. A folded type shows a +N badge with the number hidden. Collapse all/Expand all folds everything. If the selected type is hidden inside a fold, the folded row gets a dashed border. Folds are remembered per browser. Selecting a type (e.g. a newly made one) unfolds whatever hides it.
  • needs attention badge: the type could not be rebuilt from its parent after an edit (§10).
  • 🗑 on each row opens the delete dialog for that type, without selecting it.
  • Reordering: drag a type by its ⠿ grip to move it among its siblings: the other roots, or the other types derived from the same parent. Its derived types move with it. A type never changes parent this way, since that would change its derivation, so only types with siblings have a grip. The order is saved with the library, and the Multiplicity and Export dialogs follow it (§15).

6. The curve view

The selected type, drawn as a plane tropical curve. The header shows its name and the zoom, 🖌 Paint and Copy controls. If the type needs attention, a warning line with Try again appears above the picture (§10).

6.1 How curves are drawn

  • Edges are drawn in their directions, bounded edges a little thicker than ends. Ends are rays of a fixed length. Weights above 1 are in the label, e.g. e1 (w4).
  • Vertices are not drawn. Markings are drawn as dots exactly at their points, larger at vertices where more edges meet (size grows with valence − 2).
  • Lengths are chosen for readability: edges of comparable drawn length, and anything not incident kept visibly apart. No vertex lands on an edge it does not belong to, and unrelated parts do not touch.
  • Derived types are drawn like their parent, as far as possible. A type that differs from its parent by one marking looks the same except for that marking.
  • Labels (edge, end and marking names) are placed so they never overlap each other or any part of the curve. They can be turned off in Display settings. Hidden labels still appear on demand: hover over an edge or marking with a mouse, or tap it on a touch screen (tap again, or tap empty space, to hide).
  • Colors: each edge, end and marking can have its own color (§8.4, Paint mode); otherwise it uses the default color (§14).

6.2 Zoom

  • Mouse wheel or trackpad pinch zooms about the pointer. Two-finger pinch zooms on a touch screen.
  • Once zoomed in, drag to move around. A drag never counts as a click, so it never picks or paints.
  • Header controls: the zoom level, −/+ (on a computer), and Fit to show the whole curve.
  • At full view, scrolling down with the wheel scrolls the page, not the picture.
  • The zoom is kept while you edit the same type, and resets when you select another.
  • The pictures in the Add marking, Contract edge and Resolve vertex dialogs zoom the same way.

6.3 Paint mode — 🖌 Paint

  • Opens a color dialog with a color picker, preset swatches and a hex field.
  • Keep painting until I press Cancel: unticked, the next edge or marking you click takes the color and painting stops. Ticked, every click paints until you press Cancel.
  • While painting, a bar above the picture shows the color with Change color and Cancel. Escape also stops painting. Markings are drawn larger with a dashed ring, to be easy to hit. Hovering an item previews the color.
  • Each click is an ordinary color edit: saved, and passed on to derived types.
  • The last color and checkbox choice are remembered.

6.4 Copying pictures

  • Copy on the curve copies it as a PNG with a transparent background, always the whole figure, whatever the zoom, and without paint-mode decorations.
  • Copy on the dual subdivision copies it as a PNG with its background.
  • Where the browser cannot put images on the clipboard, the PNG is downloaded instead.

7. Dual subdivision

  • Below the curve, folded by default: click its heading to open it. Each vertex of the curve is dual to a cell, each bounded edge to an interior edge of the subdivision.
  • The subdivision shown matches the lengths the curve is drawn with. Cells are colored by what they are dual to: an ordinary vertex (green), a marked vertex (violet), or a crossing of the drawing (orange, always a parallelogram). A legend under the picture names the colors present. A marking part-way along an edge sits on no vertex of the plane curve, so it has no cell of its own; only markings at vertices color a cell.
  • If no subdivision can be built, a note explains why.
  • subdivision text (debug): the cells as text, with Copy. Useful for the paste box.

8. The edit panel

Everything about the selected type. It has five parts: Type, Refined multiplicity, Actions, Markings and Edges & ends. Click a part's heading to fold or unfold it. Folds are remembered, and a folded part is not computed at all (a folded multiplicity costs nothing). ⚙ Layout on the panel's title line sets their order and visibility (§8.5).

8.1 Type

  • Name: rename the type. The change applies when you leave the field.
  • Description: free text about the type, empty by default. It is saved as you type, shown (first line) in the Types panel, and stored in files. Duplicate copies it; derived types start with an empty one.
  • follow parent (propagate edits) (derived types only): whether edits to the parent reach this type (§10).
  • Duplicate: an independent copy of this type as a new root, named "… copy", with no parent and no derived types.
  • Delete…: the delete dialog.

8.2 Refined multiplicity

The type's Göttsche–Schroeter refined multiplicity, a Laurent polynomial in q (§11). Below it are each vertex's factor and the value at q = 1. If the multiplicity is undefined (a vertex that is not trivalent, or a degenerate one), the reason is shown instead.

8.3 Actions

Buttons for the operations: Edit end slope… (§9.2), Add marking… (§9.3), Contract edge… (§9.4), Resolve vertex… (§9.5) and Evaluation matrix… (§12). A button is disabled, with the reason on hover, when the type does not allow it: slope editing needs two ends, contracting needs a bounded edge, and resolving needs a vertex of valence ≥ 4.

8.4 Markings, edges & ends

  • One row per marking, and one per bounded edge and end (tagged edge or end).
  • Color control: the swatch opens the system color picker (on phones and tablets it has its own palette). With a mouse or trackpad, ▾ next to it offers preset colors. The text field takes a hex code (#rrggbb, rrggbb, #rgb). When an item has its own color, ⟲ resets it to the default.
  • Name field: rename the item. Names must be unique within the type.
  • ✕ on a marking removes it.
  • Color and name changes are passed on to derived types (§10).

8.5 Panel layout — ⚙ Layout

  • Tick a part to show it, untick to hide it.
  • Drag parts by their ⠿ grip into the order you want (§15).
  • Reset to default restores the original order with everything shown and unfolded.
  • The layout is saved in this browser only. It is not part of the library.

9. Operations

9.1 Picking on the picture

The Add marking, Contract edge and Resolve vertex dialogs show the curve so you can pick that edge or vertex directly:

  • Mouse: hovering highlights a target and names it below the picture. A click acts.
  • Touch or Pencil: a tap selects (highlighted and named), and a second tap on the same target, or the dialog's button, acts. Tapping empty space clears the selection.
  • Vertices, normally invisible, are shown as rings where they can be picked. Items that cannot be picked are faded.
  • Where targets overlap (a very short edge next to longer ones), the one nearest the pointer wins. A marking wins over the edge it sits on, and a vertex over the edges meeting there.
  • Choose from a list instead switches to a plain list. Pick on the curve instead switches back.
  • The picture zooms like the main one (§6.2).
  • In lists, a vertex is named by the edges, ends and markings that meet there, e.g. "where e1, e5, l2 meet".

9.2 Edit an end's slope

Changing one end alone would break balancing, so you choose the end to edit, its new x and new y, and a different dependent end that absorbs the change. The bounded edges are then solved again, and all other ends stay fixed. Apply changes this type, and the change is passed on to its derived types.

9.3 Add a marking

  • Pick a vertex (ringed) to put the marking there, or a point on an edge or end to subdivide it and hang the marking on the new vertex.
  • Name (optional): leave empty for an automatic name.
  • The marking is added to this type itself, not to a new derived type. It is passed on to derived types, and kept when they are rebuilt.
  • Remove a marking with ✕ in the Markings list.

9.4 Contract an edge

Merges a bounded edge's two endpoints into one vertex, creating a derived type that follows this one (§10). Only bounded edges can be contracted; ends and markings are faded. Pick the edge, then (touch) tap it again or press Contract. The new type is selected.

9.5 Resolve a vertex

Splits a vertex of valence ≥ 4 in two, joined by a new bounded edge whose direction balancing forces. The result is a new derived type. Each resolution corresponds to an adjacent maximal cell of the moduli space.

  • Pick the vertex (ringed). If there is only one, it is chosen for you.
  • Valence 4: the three ways to pair its four edges are shown as small pictures of the curves they produce, with the new edge highlighted. Hovering one shows its pairing on the big picture. Click the one you want. A pairing that would be a crossing is shown disabled.
  • Valence 5 or more (the number of splits grows fast): tick the edges to gather on one side, at least 2 and at most (valence − 2). Everything else goes to the other side. You can also click the vertex's edges on the picture. A note shows the split and the forced new edge, and a preview draws the resulting curve. Resolve applies it; it stays disabled while the split is invalid or a crossing.

9.6 Delete a type

  • Open it from 🗑 on the type's row, or Delete… in the Edit panel. It always asks for confirmation, since there is no undo.
  • By default only this type is deleted. Its derived types move up to its parent, keeping exactly the same derivation (the deleted type's steps are prepended to theirs). If it was a root, they become independent roots.
  • Also delete all N derived types (unticked by default): deletes the type together with everything derived from it, all the way down. The text and button say how many will go.
  • If the type you are viewing survives, it stays selected.

10. Derived types & propagation

  • A derived type remembers how it was made from its parent (contract this edge, resolve that vertex). When you edit the parent (slopes, markings, names, colors), each derived type that follows its parent is rebuilt by replaying those steps, and the edit reaches it. This continues down the tree.
  • Edits made directly to a derived type (a marking added to it, a color) are kept when it is rebuilt.
  • follow parent (Edit panel → Type): untick it to detach a type, so its parent's edits no longer reach it. The Types panel then shows detached.
  • needs attention: if a step cannot be replayed on the edited parent (the edge it contracted no longer exists, say), the type is left as it was and flagged. Open it and press Try again to rebuild it from the parent as it is now. Loading a file also retries flagged types once.

11. Multiplicities & balanced splits — Multiplicity

The refined multiplicity

For a curve whose vertices are all trivalent (a vertex with one marking and valence 4 counts as a marked trivalent vertex), the Göttsche–Schroeter refined multiplicity is the product over vertices of [μ(V)]q− for unmarked vertices and [μ(V)]q+ for marked ones. Here μ(V) is the lattice area of the vertex's dual triangle. A marking in the interior of an edge is not a vertex of the curve and contributes 1. At q = 1 the value is the classical (Mikhalkin) multiplicity. Values are exact.

The Multiplicity dialog

  • Lists every type in the Types panel's order and nesting, with its refined multiplicity, or "undefined — reason".
  • Subtrees fold (▾/▸, Collapse all/Expand all). Folds start as in the Types panel, but folding here does not change the panel. A folded row shows how many types it hides and how many of those are ticked.
  • Nothing is ticked when the dialog opens. Tick types, or click their names, then use Select all/Select none as needed. Types without a multiplicity cannot be ticked.
  • Check for a balanced split: searches for a way to split the ticked types into two groups whose multiplicities have equal sums, and shows the two groups and the common value. If there is none, it says so and gives the total. At least two types are needed, and at most 26.
  • Find the maximal balanced sub-collections (offered when the ticked set does not balance): lists every part of the ticked set that does split into two halves of equal total and is not contained in a larger such part, largest first. Each shows its two halves and their common total, with Tick only these to make it the selection. It handles up to 22 types (with many types it can take a few seconds) and lists at most 200.
  • Only the values at q = 1 have to balance: compares only the classical multiplicities, not the whole polynomials, in both searches. The choice is remembered.
  • Ticked types count in the search even while folded away.

12. Evaluation matrix — Evaluation matrix…

The matrix of a linear map from the type's cell of the moduli space to Rn, given by n evaluation functions, where n = number of bounded edges + 2.

Conventions

  • Coordinates of the cell: the position (x0, y0) of a chosen root vertex, and the length of every bounded edge.
  • An edge of length ℓ and direction vector u (weight included) moves its head by ℓ·u from its tail.
  • x / y of a marking: that coordinate of the marking's position, x0 (or y0) plus the sum of ℓ·u along the path from the root.
  • Cross ratio cr(p1, p2, p3, p4) of four markings or ends (markings count as contracted ends), as in Tyomkin (arXiv:1509.07453): the signed length of the intersection of the path from p1 to p3 with the path from p2 to p4. Each common edge contributes +ℓ where the two paths cross it in the same direction, and −ℓ where they cross it in opposite directions. The four must be different.

The dialog

  • Root vertex: markings first (alphabetically), then the other vertices, named by their edges (alphabetically). The first marking is chosen by default.
  • Evaluation functions (open by default): each row is x of marking, y of marking or cross ratio, with its arguments. The list starts as x and y of every marking. + Add function adds a cross ratio (or an x, if there are fewer than four legs). ✕ removes a row, and the ⠿ grip reorders rows (§15). Reset to x, y of every marking restores the start.
  • Column order (folded by default): drag x0, y0 and the edges into the order the columns should have. Default order is x0, y0, then edges by name. Reordering columns changes the determinant's sign by the permutation's sign.
  • A status line says k of n functions and what is missing. Make the matrix works only with exactly n functions and valid cross ratios.
  • Result: the matrix with row and column labels, and its exact determinant (or its rank, if singular). Any change to the root, functions or columns clears it.
  • As text: choose Python, Mathematica, Sage, MATLAB/Octave, LaTeX or tab-separated, then Copy text. The format is remembered.
  • As an image: Copy image puts a PNG (black on white, in brackets) on the clipboard, for pasting into Notability or similar apps. Download image saves it. Row and column labels adds the labels in grey.
  • Your choices for each type are kept while the page is open.

13. Saving, files & Google Drive

13.1 Autosave

Every change is saved in this browser at once (the top bar shows when). The library comes back when you reopen the page on the same device and browser. It is not shared between browsers or devices: use Export/Import or Google Drive for that. Clearing the browser's site data erases it, so export or save to Drive what matters. View preferences (panel widths, folds, display settings, Edit-panel layout) are also kept per browser, but are not part of the library.

13.2 Export — Export…

  • Lists every type in the Types panel's order. Nothing is ticked at first.
  • Select with N derived ticks a type and everything derived from it. When all of those are ticked it reads Unselect with N derived. Select all/Select none too.
  • Subtrees fold, as in the Multiplicity dialog. Ticked types are exported even while folded.
  • Export downloads a JSON file: tropical-workspace.json for everything, the type's name for one type, tropical-subset-N.json otherwise.
  • A subset is exported consistently. A type whose parent is left out is re-attached to its nearest included ancestor, carrying the steps in between, or becomes a root if there is none.

13.3 Import — Import

  • Choose a JSON file (from Export or Drive). On a phone or iPad, the file picker can also reach Google Drive or iCloud through the Files app.
  • If the library is not empty, you choose: Add to the library or Replace the library (which discards the current types).
  • Added types keep their derivations. If a name is already used, the imported one gets a number, e.g. "root (2)".
  • A bad file is reported, and the library is left untouched.

13.4 Google Drive — ☁ Drive…

  • Sign in with Google opens Google's sign-in window. The app asks only for access to files it creates; it cannot see anything else in your Drive. The sign-in lasts about an hour, or until the page is reloaded, and is never stored.
  • Save the library: Save as a new file saves under the name you type. This browser then remembers that file (linked), and Save to "name.json" updates it from then on. Unlink forgets the link.
  • If the Drive copy was changed after this browser last saved or opened it (from another device, say), saving warns you: Overwrite it, Save as a new file instead or Cancel.
  • Open from Drive: lists the app's files, newest first, with Open and Refresh. Opening goes through the same add-or-replace choice as Import. Replacing links the library to that file.
  • Sign out ends the session.
  • Messages you may see: sign-in was cancelled; allow pop-ups for this site; your Google session expired — press the button again; or the linked file is no longer in Drive, in which case you can save a new one.

13.5 GitHub — ⑂ GitHub…

Keep the library in a GitHub repository and work on it there: open a file, commit changes back, use branches, look at the file's history and open pull requests.

Access: a token

Public repositories open without anything. To commit (or to read a private repository) the app needs a fine-grained personal access token; the site has no server, so GitHub's usual "sign in" cannot be used. To make one:

  1. On GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token (the dialog has a direct link).
  2. Repository access: Only select repositories → your repository.
  3. Permissions → Repository: Contents: Read and write; for pull requests also Pull requests: Read and write. Choose an expiry date.
  4. Copy the token, paste it in the dialog and press Save token. The app checks it and shows the account. It is kept in this browser and sent only to GitHub; Forget token removes it.

Opening

  • Repository: owner/repo, or paste a GitHub link (to the repository, a branch or the file itself), then Load.
  • Branch: the default branch is chosen first; the list shows the branch's .json files, each with Open.
  • Opening goes through the same add-or-replace choice as Import. Replacing links the library to the file (shown under Linked file, with the commit it was read at); adding does not.
  • Commit as a new file adds the library to the chosen branch under a new name, and links it.

Committing

  • Write a commit message and choose Commit to branch (the branch it was opened from, the default) or Commit to a new branch (named for you; change it if you like). A new branch starts at the commit the file was read at. Press Commit.
  • Conflict check: if the file changed on that branch after you opened it, nothing is overwritten. You choose Commit to the new branch instead, Overwrite on branch (replaces the newer version) or Cancel.
  • Pull request: when the linked branch is not the default branch (e.g. after committing to a new branch), give a title (and a description) and press Open pull request; a link to it appears.

History

  • Show history lists the file's commits on the branch: message, short id, author, date.
  • Open this version loads an older version. Committing from it goes through the conflict check (the file has changed since), so you can put it on a new branch.
  • Unlink forgets the linked file.

Messages you may see: the token was rejected (expired or mistyped — forget it and paste a new one); the token is not allowed to do this (check its repository and permissions); not found (check the repository, branch and path; a private repository needs a token); the rate limit is used up (without a token GitHub allows few requests per hour).

14. Display settings — 🎨 Display

  • Default edge / end / marking color: the color of everything without its own color. Use automatic (theme-based) follows light/dark mode.
  • Labels: show or hide edge and end names and marking names. Hidden labels still appear on hover or tap (§6.1).
  • Background: the color behind the curve. Pick one, use a swatch, or Use automatic (system light/dark). The page, borders and text adapt to it. Match it to wherever you paste pictures.
  • Settings apply at once and are remembered per browser.

15. Reordering lists

Every list you can reorder (the types in the Types panel, the Edit panel layout, and the evaluation functions and columns) works the same way:

  • Drag an item by its ⠿ grip. It follows the pointer and the others slide aside. Drop it where you want it.
  • With a mouse you can also grab a row by its empty space (not in the Types panel, where a click selects the type). With a finger or Pencil, use the grip: touching elsewhere scrolls as usual.
  • Hold the item near the top or bottom edge of the dialog or page to scroll it.
  • Escape during a drag puts the item back.
  • Keyboard: focus a grip (Tab), then ↑/↓ move its item.

17. Help in the app

  • ? next to a panel's or dialog's title opens a short explanation of its purpose, features and buttons, with a link to the matching part of this guide. Click (tap) it again, click elsewhere or press Escape to close it.
  • ? Help in the top bar gives an overview of the top bar and a link to this guide.
  • Many buttons also explain themselves when you hover over them.

18. Troubleshooting

  • A button or the help popovers do not respond, or look unstyled. The browser showed an old cached copy of the page. Reload it; the app also repairs such a page by itself when it starts.
  • The app did not update / a new feature is missing. Compare the version in the top bar (e.g. v46) with the expected one, and do a hard refresh (Ctrl/⌘+Shift+R; on an iPad, close and reopen the tab).
  • "needs attention" on a type. Its parent was edited in a way its derivation cannot follow. Select it and press Try again, or delete and redo it (§10).
  • A resolution is disabled ("crossing"). That split's new edge would have direction 0. It realizes as a parallelogram, not an edge, and cannot be applied.
  • The refined multiplicity says "undefined". Some vertex is not trivalent (resolve it first), or is degenerate. The reason names the vertex.
  • GitHub says the token is rejected or not allowed. Make a new fine-grained token for that repository with Contents: Read and write (and Pull requests for pull requests), and paste it after Forget token (§13.5).
  • Google sign-in does not open. Allow pop-ups for the site (on an iPad: Settings → Safari). If it says the session expired, press the button again.
  • My library is gone. The browser's site data was cleared, or you are in another browser, device or private window. Import an exported file or open it from Drive.
  • A copied picture looks wrong where I paste it. The curve copies with a transparent background. Choose a matching background in Display settings so colors read well.
